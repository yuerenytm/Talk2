# 技术选型

本文记录 Talk2 当前采用的技术栈。产品范围见 [产品介绍.md](./产品介绍.md)，模块怎么拆见 [架构设计.md](./架构设计.md)。

## 主栈

| 层级 | 选择 | 说明 |
|------|------|------|
| UI | **PySide6** | Windows / Linux 同一套窗口、托盘、弹窗；LGPL |
| 路径 | **platformdirs** | 用户数据目录随操作系统走规范位置 |
| AI | 官方 **openai** SDK | 流式、超时、SSE 现成；换厂商改 `base_url` + `model` |
| 存储 | 标准库 **sqlite3**（WAL） | 单文件、可检索，备份即拷贝数据库 |
| 密钥 | **keyring** | Win：凭据管理器；Linux：Secret Service |
| 新闻 | **feedparser** + 用户可配 RSS | 公开源拉取后再交给 AI 摘要 |
| 定时 | 进程内 **QTimer** | 与 Qt 事件循环一致，到点弹窗 |
| 网络 | **httpx**（RSS）；LLM 走 SDK 自带 httpx | — |
| 打包 | **PyInstaller**（在目标 OS 上打） | Windows 与 Linux 均出单目录，目录内为可执行文件及依赖 |
| 单实例 | **QLockFile** | 锁放在用户数据目录 |
| 通知辅助 | Qt `QSystemTrayIcon.showMessage()` | 新闻主界面仍是独立弹窗 |
| 知识库 | SQLite **FTS5** + API **embeddings** | 指定文件夹内 Markdown 切块索引；关键词与语义融合检索 |

业务逻辑一套代码；数据目录、密钥后端、开机自启、托盘可用性、知识库索引放进薄适配层。先做「进程常驻 + 到点弹窗」，知识库随聊天能力一起接上。

## 1. 桌面 UI

需求：多窗口（聊天 / 设置 / 新闻弹窗）、流式长文本、托盘常驻、知识库文件夹选择与检索结果展示。目标平台 Windows 与 Linux。

**PySide6**：一套代码覆盖双平台；窗口、托盘、置顶弹窗、信号槽驱动的流式气泡都成熟；许可证 LGPL；Qt6 对 Windows 与 X11/Wayland 有官方支持。打包体积常 80MB+；默认观感偏 Qt，用轻量 QSS 即可。

### UI 层约定

- 聊天布局：左侧会话列表、右侧消息流、底部输入。
- 消息支持 Markdown 渲染。
- AI 回复在 `QThread` / `QObject` worker 里跑，用 signal 回主线程刷新。
- 字体：Windows 优先 `Segoe UI` / `Microsoft YaHei UI`；Linux 走 Qt 默认，缺中文时回退 `Noto Sans CJK` / `WenQuanYi`。

### Linux 托盘与 Wayland

- KDE / XFCE / Cinnamon / Windows：`QSystemTrayIcon` 通常可用，关闭聊天窗即退到托盘。
- 部分桌面环境没有传统托盘：启动时检测 `QSystemTrayIcon.isSystemTrayAvailable()`，托盘可用则隐藏到托盘，否则主窗口最小化到任务栏。
- Wayland 上置顶可能被合成器忽略。新闻窗先 `show()`、`raise_()`、激活窗口，置顶作为尽力而为。

## 2. AI 交互

用户填写 `base_url`、`api_key`、`model`，对接 OpenAI 兼容接口（OpenAI、DeepSeek、通义兼容模式、Moonshot、Groq、本地 Ollama 等）。

**openai SDK**：流式、超时、重试、SSE 现成；换厂商通常只改 `base_url` + `model`。其它协议需要时再加适配器。

### 用户可配项

- `base_url`、`model`、`api_key`
- `timeout`、可选 `system_prompt`、温度、最大 token、embedding 模型名
- 知识库文件夹路径
- `api_key` 走 keyring

### 密钥

**keyring**：Windows Credential Manager；Linux Secret Service（GNOME Keyring / KWallet）。无图形密钥环时，设置页提供「仅保存在当前进程内存」。

## 3. 本地存储

SQLite 单文件、可检索、标准库即可，备份即拷贝 `talk2.db`。密钥走 keyring。数据目录用 platformdirs。

路径约定：

- Windows：`%APPDATA%\Talk2\`
- Linux：`~/.local/share/Talk2/`（库与日志），`~/.config/Talk2/`（非敏感配置）

表结构见 [架构设计.md](./架构设计.md)。

## 4. 本地 RAG（Markdown 知识库）

用户在设置中指定一个文件夹（例如 Obsidian 库根目录）。应用递归读取其中的 `.md` 文件，按 ATX 标题（`#` / `##` 等）切块，记下相对路径与标题路径，便于结果里直接显示「哪篇笔记的哪一节」。

检索做两路融合：

- **关键词**：SQLite FTS5，中文用 `jieba` 分词写入；适合「拉萨旅行计划」这类专有名和标题命中。
- **语义**：同一套 OpenAI 兼容接口的 embeddings（设置里可单独填 embedding 模型名），向量存在 SQLite 中，查询时用 `numpy` 做相似度排序。

索引按文件 `mtime` 增量更新，配合 `QFileSystemWatcher` 在库有改动时后台刷新。对话开启知识库时：先取 Top-K 块注入上下文，流式作答，并在气泡或侧栏给出引用（文件路径 + 标题路径），可调用系统默认方式打开该 Markdown。

## 5. 新闻简报

链路：**公开 RSS → 用户配置的 AI 摘要成 10 条 → 到点弹窗**。

- **feedparser**：源可配。默认给一组中文/国际源，用户可改。每次取最近标题和摘要，截断后送给模型。
- 摘要用同一套 LLM 客户端、专用 prompt，输出 10 条（标题 + 一两句 + 来源）。
- API 暂时不可用时，弹窗展示原始标题 Top 10，并标明「未摘要」。

**QTimer + 进程常驻**：双平台同一套逻辑，到点直接弹 `NewsPopup`，和聊天同进程。设置页提供开机自启，以便到点一定能推送。

弹窗是主界面（独立窗口、10 条列表、「稍后」/「打开助手」）。到点时若正在聊天，另开窗口，输入不受影响。辅助提醒用 Qt 托盘 `showMessage()`；通知服务就绪时同时弹出系统通知。

## 6. 进程、自启、打包

- 单进程：Qt 主线程负责 UI，worker 线程做网络与摘要。
- 单实例：用户数据目录里的 `QLockFile`。
- 开机自启（设置页开关）：
  - Windows：当前用户 Startup 快捷方式
  - Linux：`~/.config/autostart/talk2.desktop`（XDG Autostart）
- PyInstaller 由 `scripts/build.py` 在目标操作系统上执行，产物为 `dist/Talk2/`。目录内带齐 Qt 平台插件与 jieba 词表，HTTPS 使用操作系统证书库。说明见 [打包.md](./打包.md)。
